# 河流宽度规则与历史兼容

生效日期：2026-10-03。

新建河流采用 width_mode: distance。未设置宽度的控制点按宽度锚点间的累计路径长度插值；路径长度使用当前六边格河道的步长。仅细分同一路径不会改变其宽度分布。没有锚点时使用默认宽度 4，锚点范围外延续最近锚点的宽度。

没有 width_mode 的旧文件和旧数据库河流在读取时标记为 legacy，继续使用控制点序号插值。读取、查看和导出不会改写原文件或执行整库迁移。JSON 导出保留该模式，供当前版本正确往返读取。

当用户用新编辑器修改旧河流时，系统先计算原控制点的有效宽度并转成显式锚点，再使用距离规则。已有隐式控制点的外观保持；新插入的无宽度控制点按距离插值。界面的宽度草稿同步显示这些锚点。显式传入 null 可以移除宽度锚点。

新持久历史在 summary 中记录 rules_version: 2。历史条目缺少该版本时，撤销和重做使用原河宽规则。新操作的逆操作保留原河流的模式和锚点，因此可以跨越新旧操作连续撤销重做。内存历史保存完整文档，同样保留模式。

回归覆盖：

- 新河流插入无宽度控制点后，整个宽度序列保持一致。
- 不等长河段按照累计长度分配宽度变化。
- 旧 JSON 读取和导出保留有效宽度。
- 旧河流重命名及路径细分保留原有有效宽度。
- 数据库中旧宽度操作与新操作交错后，连续撤销重做仍得到各自原来的结果。
- 原始旧地图文件保持不变，恢复可使用原文件及正常 SQLite 备份流程。

实现位于共享核心包的 rivers.ts、serialization.ts 和 commands.ts；服务端的分页读取、流式导出及历史执行也使用相同约定。
