# 前端操作与布局审查

日期：2026-10-02。审查对象：`be10266` 的 React 编辑器。

前端需要同时重构编辑状态和工作区布局。已复现的问题涉及草稿丢失、跨地图提交、
批量字段被意外清空和重复提交。布局问题则让这些操作更难理解和检查。

本次交付包含审查证据和[独立交互原型](../../design/editor-v2/README.md)。
原型使用内存示例地图；下述正式应用缺陷尚未在 `apps/web` 中修复。

## 五项实际复现

运行真实 hooks，使用内存 DOM、受控地图数据和提交替身。
这验证了状态转换及提交载荷，没有修改用户地图，也不模拟网络和数据库的全部行为。

- [复现脚本](./probe-interactions.mjs)
- [原始结果](./interaction-results.json)

| 编号 | 优先级 | 操作与实测结果 | 代码位置 |
| --- | --- | --- | --- |
| F1 | P1 | 选中单元格并输入备注后，把它移出加载视口：选中对象变成 `null`，备注清空，`dirty` 变为 `false` | [useCellEditor.ts](../../../apps/web/src/useCellEditor.ts)，65–73、316–324 行 |
| F2 | P1 | 在地图 A 绘制两个河流点，切到地图 B 后完成：草稿仍处于绘制中，提交目标变成 B | [useRiverEditor.ts](../../../apps/web/src/useRiverEditor.ts)，122–138、172–272、310–318 行 |
| F3 | P1 | 批量编辑只设置地形为丘陵，提交却还包含 `biome: null`、`tags: []`、`note: ""`，会清掉原有字段 | [useAdvancedEditor.ts](../../../apps/web/src/useAdvancedEditor.ts)，176–201 行 |
| F4 | P2 | 连续调用两次应用，在任何响应返回前已经发出两次修改 | [useCellEditor.ts](../../../apps/web/src/useCellEditor.ts)，185–211 行 |
| F5 | P2 | 批量选中一格，把该格移出加载视口：选中数量从 1 变成 0 | [useAdvancedEditor.ts](../../../apps/web/src/useAdvancedEditor.ts)，297–306 行 |

F1/F5 的共同原因是把 `activeCells` 同时用作视口渲染数据和编辑对象的完整来源。
离开视口只意味着当前不渲染，不能据此判断对象已删除。

F2 中，未创建完成的河流没有已选河流 ID，现有重置逻辑没有覆盖地图身份变化；
`riverDirty` 又要求有已选河流，无法完整表达新建草稿。

F4 的提交入口缺少统一的进行中状态。按钮禁用只能改善反馈，正式修复还需要
命令去重、按地图提交次序和响应归属检查，配合后端事务及版本检查。

复现方式，从仓库根目录执行：

```sh
node --import ./apps/server/node_modules/tsx/dist/loader.mjs docs/research/2026-10-02/probe-interactions.mjs
```

## 从代码与页面确认的其他问题

| 问题 | 对用户的影响 | 重构要求 |
| --- | --- | --- |

| [App.tsx](../../../apps/web/src/App.tsx) 22–27、116–135、339–379 行同时协调 `interactionMode`、格式刷开关与河流绘制状态 | 工具切换依赖多处手工复位，新增工具会继续扩大组合状态 | 一个工具状态机处理进入、退出、临时平移和草稿保护 |
| 新建、导入、复制、重置、切图入口分散在 App 与 workspace | 草稿保护没有覆盖统一的离开编辑会话边界 | 所有会话切换走同一入口；取消、保留、应用的语义一致 |

| 河流属性包含 Points / Width anchors 等文本语法；[MapCanvas.tsx](../../../apps/web/src/MapCanvas.tsx) 738 行将河流层设为不可点选 | 用户需要理解数据表示才能修改河流，画布与属性难以对应 | 河流命中区域、可视控制点、宽度控件；文本形式放到可折叠高级区域 |
| [MapCanvas.tsx](../../../apps/web/src/MapCanvas.tsx) 248 行给每个可见格设置 `tabIndex=0` | Tab 路径随格数变长，缺少统一的画布导航 | 画布作为一个主要 Tab 入口，方向键移动，明确焦点和键盘操作反馈 |
| 画布禁用原生触摸行为，但拖动状态只有一个指针 | 移动设备缩放与多指操作需要专门设计 | 正式实现并在真实设备上检查单指、双指、取消手势；保留可见缩放按钮 |
| `appendRiverPoint` 的 state updater 内调用其他状态更新 | 更新函数混入副作用，难以推导重复执行时的行为 | 用纯 reducer 计算状态；提示和提交在事件或副作用边界处理 |

前一轮还复现了地图名称被视口响应覆盖、旧打开请求把当前地图切回去，详见
[架构审查 R5、R8](./README.md)。这些问题应与本轮状态重构一起处理。

## 布局实测

原版在空地图界面已展示约 94 个按钮、输入或选择控件。右栏的单格、格式刷、河流、
批量和替换功能同时展开，1440 × 900 时内容滚动高度约 3475 像素。

| 浏览器视口 | 原版画布区域 | 新原型默认画布区域 | 主要变化 |
| --- | --- | --- | --- |
| 1440 × 900 | 810 × 811 | 876 × 814 | 58 高顶栏、60 宽工具栏、204 宽内容栏、300 宽上下文属性栏 |
| 1024 × 768 | 448 × 583 | 684 × 682 | 内容栏收起；工具栏与属性栏仍可并排 |
| 375 × 812 | 359 × 500；页面总高约 5235 | 325 × 730；页面总高 812 | 保留画布，内容与属性按需打开；属性使用底部抽屉 |
| 812 × 375 | 本轮未测原版 | 752 × 289；页面总高 375 | 短窗口工具栏内部滚动，底部状态栏保持可见 |

尺寸来自浏览器 DOM，表格四舍五入到整数。原版使用空地图，原型使用 546 格示例，
以上比较的是空间分配，不是渲染性能。
原型1440宽默认单格属性内容区高678像素，无内容溢出；更多控件由工具上下文切换呈现。

## 正式重构顺序

1. 把 F1–F5 的复现转成有意义的回归测试，同时修复提交事务、版本和历史一致性。
2. 引入地图编辑会话，将地图身份、持久化数据、草稿、选区、工具和视口缓存分开。
3. 所有修改通过一个命令提交入口；响应校验地图 ID、会话代次和请求版本。
4. 将新工作区壳与上下文属性组件接入现有 React 项目，保留共享地图规则与渲染能力。
5. 完成河流控制点、全图修改预览、失败重试、真实触摸和无障碍验证，再用大地图评估渲染瓶颈。

布局和交互契约见[编辑器设计说明](../../design/editor-v2/README.md)。
